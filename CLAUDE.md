# «Бизнес-класс!!!» — правила проекта

Браузерная 3D-версия российской настольной игры 2001 года. Фанатский некоммерческий проект,
вносить изменения в репозиторий может только владелец.

## Язык

- Общение с владельцем, комментарии в коде, тексты интерфейса, журнал партии и названия тестов — **на русском**.
- Сообщения коммитов — **на английском**: короткий заголовок в повелительном наклонении без точки
  («Throw dice beside the mover…»), затем абзац о том, что видит игрок и почему так сделано.

## Стек и команды

TypeScript (strict) + React 19 + Vite, 3D на three.js, физика кубиков на cannon-es, состояние — zustand,
сеть — WebSocket (`ws`) или WebRTC (PeerJS). Тесты — vitest.

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер Vite на :5173 (проксирует `/ws` и `/api` на :8787) |
| `npm test` | `vitest run`: сценарии движка и тесты кубиков |
| `npm run build` | `tsc --noEmit` + `vite build` в `dist/` |
| `npm run host` / `npm start` | сборка + локальный сервер `server/index.mjs` (раздаёт `dist/`, ретранслирует WS) |
| `npm run assets` | пересобирает `public/res` из `../Resources` (вне репозитория) |
| `npm run art` | генерация арта в `public/art`, нужен `MAGNIFIC_API_KEY` (платно, запускать только по просьбе) |
| `npm run models` | Blender в фоне: `blender/make_pieces.py` → `public/models/pieces.glb` |

Перед коммитом: `npm test` и `npm run build` (проверка типов) должны проходить.

## Архитектура

- `src/engine/` — **игровое ядро, независимое от UI, 3D и сети.**
  - Состояние `GameState` — чистый JSON. Меняется только через `applyAction(state, action)`,
    которая клонирует состояние и возвращает `{ state, events, error? }`. Ошибка — строка на русском,
    состояние при этом не меняется.
  - Случайность — только через seeded RNG в `s.rng` (`util.ts`), никакого `Math.random` в ядре:
    партии должны воспроизводиться по seed, а хост и клиенты — сходиться.
  - Не импортировать в ядро ничего из `ui/`, `three/`, `net/`, `store.ts`.
  - Вопросы игрокам и ролям — через `ask()` / `Prompt`; события для анимаций — `GameEvent`.
  - Новое действие: добавить вариант в `Action` (`types.ts`), обработать в `dispatch` (`engine.ts`),
    проверить, кто имеет право (`by`), покрыть сценарием в `scenarios.test.ts`.
  - `rulings.ts` — утверждённые трактовки мест, где буклет неоднозначен. Действуют во всех партиях.
    Новую трактовку не придумывать молча: спросить владельца и записать сюда с комментарием.
- `src/store.ts` — zustand-стор: экраны, авторитетное `state` и показанное `view` (отстаёт на время
  анимаций через `queue`), сохранения в `localStorage` (`bk.*`), сеть и лобби.
- `src/net/transport.ts` — хост авторитетен: держит состояние и применяет действия; клиенты шлют
  намерения (`action`) и получают готовое состояние. Сообщения — `NetMsg`.
- `src/three/` — сцена стола (`TableScene.ts`: камера, фишки, анимации по `GameEvent`) и симуляция кубиков (`dice.ts`).
- `src/ui/` — React-экраны и панели; стили — в `src/styles.css`.
- `server/index.mjs` — минимальный Node-сервер без сборки (обычный ESM).
- `public/sw.js` + плагин `precacheManifest` в `vite.config.ts` — офлайн-кеш; `precache.json` пишется при сборке.

## Данные

- `public/data/board.json` — источник истины для поля (клетки, группы, переходы, автострада, биржа,
  рулетка). Координаты `xy` — в системе 2048×2048, независимо от размера текстуры `board.jpg` (4096).
  `tools/gen-board.mjs` — одноразовый генератор, повторно не запускать.
- `public/data/cards.json`, `glossary.json` — карточки и глоссарий/страницы правил.
- Поля с кириллическими ключами (`проверить`, `требует_оцифровки`, `примечание`) — пометки для
  ручной проверки, показываются в редакторе (`Editor.tsx`). Не удалять без подтверждения.
- Сохранённые партии содержат копию `data` и `v: 1`. Меняя форму `GameState`, учитывать старые сохранения.
